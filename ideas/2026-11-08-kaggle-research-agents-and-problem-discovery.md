# 从 Kaggle 冠军工作流到“能发现问题”的自主机器学习研究系统

> **状态**：研究想法 / 待验证（不是已经实现或实测的系统）  
> **整理日期**：2026-11-08  
> **主题**：Kaggle、AutoML、Machine Learning Engineering Agents、科学发现、多 Agent、假设检验、实验记忆  
> **核心研究问题**：如何让一个 AI 研究系统不仅优化给定指标，而且能发现隐藏的数据结构，重新表述问题，设计可能推翻自身结论的实验，并在长期研究中积累可靠知识？
>
> 本文是系列讨论的研究整理：将**已经有公开证据的做法**、**从冠军案例推导出的判断**和**尚未验证的新设计**分开。它不声称提出了一套已有科学验证的最优架构。

## 0. 一页摘要

当前机器学习 Agent（如 AIDE、R&D-Agent、MLE-STAR、MLEvolve、ML-Master 2.0）已经能形成“生成方案—执行训练—计算指标—修复/优化”的自动循环；多 Agent、树/图搜索、经验记忆和消融实验正在提高搜索效率。但是，**得到更高的分数不等于理解了问题**。

真实 Kaggle 冠军的关键贡献经常发生在比模型选择更上游的位置：

1. 识别数据产生机制与隐藏结构，例如匿名交易背后的用户关系。
2. 重新定义预测的中间任务，例如把多日预测拆成不同预测步长。
3. 发现必须先求解的子问题，例如医学影像中先定位再分类。
4. 选择贴近真实测试分布的验证设计，并持续质疑这一设计。
5. 通过相互独立的研究路线和错误分析发现可互补的信号。

**研究假说 H0（待检验）**：相比只维护代码/分数搜索树，显式维护“观察—竞争解释—鉴别实验—证据—问题重构”的知识结构，可能在固定计算预算下提高独立发现新结构的能力；但也可能只增加开销、制造空洞解释，必须用消融实验检验。

**不应过早下的结论**：当前 Agent 不会发现问题、冠军主要靠领域直觉、增加 Agent 数量必然提升探索广度、对抗讨论必然逼近真相、或 Kaggle 分数高等同于科研能力高。这些均需要区分条件和证据。

## 1. Kaggle 研究的现实工作流

### 1.1 常见工具栈（按任务选择，不是冠军必备清单）

| 层面 | 常见工具/方法 | 真正承担的角色 |
| --- | --- | --- |
| 数据探索 | Python、Jupyter、pandas、Polars、SQL、NumPy、Plotly | 认识分布、实体、缺失模式、时间/群组结构 |
| 表格建模 | LightGBM、XGBoost、CatBoost、scikit-learn | 快速建立强基线，验证特征假设 |
| 深度学习 | PyTorch、timm、Transformers、PEFT 等 | 图像/文本/音频及复杂表示学习 |
| 时间序列 | 滞后/滚动特征、时间切分、树模型或序列网络 | 处理预测步长、时变性、历史可用性 |
| 实验搜索 | Optuna、脚本化搜索、手工或 Agent 驱动实验 | 提高候选方案的试验效率 |
| 实验资产 | Git、配置文件、日志、MLflow/W&B、Parquet、OOF 预测 | 可复现、比较、审计和集成 |
| 执行 | Kaggle Notebook、GPU、容器、云实例 | 在成本与时限约束下完成试验 |
| 提交 | Kaggle API/Notebook、完整推理脚本 | 保证最终方案可运行且符合竞赛约束 |

表格、图像、时序、文本及代码竞赛的技术栈差异很大。LightGBM 常见但不是“所有 Kaggle 比赛”的统一最优模型。

### 1.2 冠军队伍的典型阶段（抽象工作流，不是每队固定日程）

1. **理解赛题**：目标、评价指标、训练与测试的来源、允许数据范围、提交和推理规则。
2. **数据侦察**：缺失、重复、身份/群组、时间、异常值、训练测试分布差异、可疑泄漏。
3. **建立 Baseline 与本地验证**：先回答“我们怎么知道一个改动真正有效？”
4. **并行生成研究假设**：特征、数据机制、任务分解、模型、损失函数和外部知识等不同路线。
5. **大量小型、可复现实验**：留存配置、代码版本、分折指标、OOF、运行耗时与失败结论。
6. **错误分析与重构问题**：分析特定样本群体、时间段和模型间分歧，不局限于看单个分数。
7. **集成与稳健性检验**：多模型/多特征视角是否真正互补；融合层必须避免验证泄漏。
8. **最终候选锁定**：完整推理路径、时限、环境、私榜风险、可重复运行。

这更像连续科研，不是“EDA → 模型 → Optuna → 提交”的一次性流水线。冠军与金牌也不能混同：稳定进入金牌区、偶然赢一场和普遍可迁移的研究能力是不同命题。

### 1.3 典型实验单元

每次实验最好包含：

- 研究问题与可证伪的假设，而不只是“尝试 XX 模型”；
- 与哪个对照组比较，改动了什么，哪些变量保持不变；
- 数据版本、切分规则、随机种子、代码和依赖；
- 分折分数、按群体误差、置信区间或重复运行、用时与成本；
- OOF/预测文件、失败和异常日志；
- 结果支持/反驳了什么、未能排除的替代解释、下一步实验。

一个单模型较弱的结果也可能具有集成价值；一个单次 CV 提升也可能是噪声或泄漏。实验记录需要超越“best score”。

## 2. 三个真实冠军案例：改变的不是只有参数

### 2.1 IEEE-CIS Fraud Detection（2019）：发现隐藏实体

**赛题**：识别交易欺诈，交易字段中有部分匿名化或含义不完整的变量。

**冠军方向**：结合银行卡/地址字段和交易时间相关变量构建近似客户身份，研究相同客户的历史和交易关系；同时重视时间切分与不同模型的互补。Chris Deotte 的公开复盘与后续技术总结强调了客户 UID 和特征聚合的价值。

**这里真正值得测试的研究能力**：

- 能否从“某些时间差变量异常稳定”观察到可能存在隐藏身份？
- 能否把“字段组合是身份标识”与“只是时间段或采集机制的伪相关”列成竞争假设？
- 能否设计独立时间段、已知/未知客户、消除某字段后的验证来鉴别？
- 能否把一张独立交易表重新看作“隐含实体—交易事件”的关系数据？

应避免直接把竞赛中的身份恢复做法称为因果发现；恢复 ID 是一个可验证的数据结构推断，非自动获得因果解释。

来源：
- [IEEE-CIS 冠军讨论 Part 1](https://www.kaggle.com/competitions/ieee-fraud-detection/discussion/111284)
- [IEEE-CIS 冠军讨论 Part 2](https://www.kaggle.com/competitions/ieee-fraud-detection/discussion/111308)
- [NVIDIA / Chris Deotte 技术总结](https://developer.nvidia.com/blog/leveraging-machine-learning-to-detect-fraud-tips-to-developing-a-winning-kaggle-solution/)

### 2.2 Rohlik Sales Forecasting Challenge（2025）：改写预测问题

**冠军公开思路**：从单个 LightGBM 基线出发，发现对未来 14 天分别预测有收益；深入构造商品相对品类价格/折扣、竞争品可用性等特征；最终结合 XGBoost 与 LightGBM，并为不同预测日训练多个模型（共 28 个）。

关键发现不是“树模型神奇”，而是**预测距离不同，可能对应不同统计机制**。一个统一预测函数与多个按预测步长建模的函数属于不同的任务分解假设，必须用实验比较。统一模型也能显式接收预测步长，因此分开训练不是普适最优。

冠军还报告了无效尝试（CatBoost、异常剔除、某些递归预测与子群专用模型），以及训练成本与榜单分数之间的权衡。这些失败记录与成功同样有研究价值。

来源：[Rohlik 2025 一等奖方案（Kaggle 原始复盘）](https://www.kaggle.com/competitions/rohlik-sales-forecasting-challenge-v2/writeups/golden-1st-place-solution)

### 2.3 RSNA 2024 Lumbar Spine：发现必须解决的中间任务

**冠军队伍**：Avengers；原始冠军复盘署名 NANACHI。

核心不是把所有 MRI 图像直接塞进更大的分类器，而是建立多阶段结构：关键切片/实例序号预测、空间坐标预测、相关区域裁剪，再进行病变严重程度分类。冠军还报告了 MIL、模型选择、错误传播增强及失败尝试。

这里体现了**任务因子分解**：全图到疾病标签的映射，可被“定位 → 对齐 → 局部判断”替代。研究系统需要探索的不只是网络架构，还包括任务图和中间变量。

来源：
- [RSNA 2024 冠军方案](https://www.kaggle.com/competitions/rsna-2024-lumbar-spine-degenerative-classification/writeups/avengers-1st-place-solution)
- [RSNA 官方冠军名单](https://www.rsna.org/media/press/i/2554)

### 2.4 从三个案例得到的共同命题

冠军的突破往往发生在“模型可利用的信息和任务结构是什么？”这个层面，形式包括：

- **隐变量恢复**：匿名字段其实指向同一实体；
- **任务重新分解**：不同预测步长或子群并不宜一刀切；
- **先验中间任务**：先解决定位、分割、关联，再做最终预测；
- **重新设计验证**：排行榜最优方向不一定适合时间外推或新群体；
- **发现模型互补机制**：集成收益不仅来自随机种子差异，还可能来自建模视角差异。

这些是对公开案例的归纳，**不是**对所有冠军的统计定律。

## 3. 已有工作流、Agent 和评测体系

### 3.1 行业流程 ≠ 自主研究算法

- **CRISP-DM**：业务理解、数据理解、数据准备、建模、评估、部署。适合定义项目阶段，但不解决怎样自动生成有价值的假设。
- **Microsoft Team Data Science Process**：团队项目和交付组织方式，偏工程协作。
- **冠军复盘/Notebook**：具体研究行为和领域洞察的高价值记录，但样本有幸存者偏差，复盘通常没有完整记录全部失败试验。

### 3.2 代表性 MLE Agent（按最值得借鉴的机制比较）

| 系统 | 已公开的核心机制 | 启示 | 不能由论文/榜单直接推出 |
| --- | --- | --- | --- |
| AIDE / aideml | 以候选代码为节点的实验树，生成—调试—改进—评分 | 代码搜索树、可重放实验史 | 一定具有独立发现隐藏数据机制的能力 |
| Microsoft R&D-Agent | Research 提假设、Development 实现、评测反馈持续迭代 | R/D 职责区分和研发闭环 | 每次假设都具备真正科学鉴别力 |
| Google MLE-STAR | 外部检索、代码模块消融、定向改进和集成 | 用消融缩小搜索粒度 | 能普遍发现训练目标或样本生成机制的错误 |
| MLEvolve | Progressive Monte Carlo Graph Search、跨分支融合、经验检索、多模式生成 | 多路线探索与跨分支知识复用 | 更多搜索分支必然产生多样化解释 |
| ML-Master 2.0 / EvoMaster | Hierarchical Cognitive Caching，长期策略与执行细节分层 | 将多轮经验压缩成长期可用知识 | 压缩后的“经验”总是正确且可迁移 |

### 3.3 Benchmark 要读“测量了什么”，不只看数字

**MLE-bench**（ICLR 2025）整理 75 场历史 Kaggle 任务，衡量端到端机器学习工程能力。原始论文中 o1-preview + AIDE 达到至少铜牌水平的比例是 16.9%。官方仓库后续榜单收录了明显更高的结果，并于 2026-04-24 暂停接收新提交，以改进公平性和可比性。

必须分清：

- “达到至少铜牌门槛的任务比例”不是金牌率，也不是冠军率。
- MLE-bench 全量与 Lite 子集、不同基础模型、预算（12h/24h）、提交规则不可直接横向归因于架构。
- MLEvolve 项目材料与官方榜单可能出现不同时间/配置下的数字；引用时以明确实验设置、日期和原始评价报告为准。
- 历史 Kaggle 题目可能存在论文/Notebook/公开冠军方案的预训练数据污染。
- 达到高分不等于证明系统自主发现了哪些新的问题解释。

参考：[MLE-bench 论文](https://proceedings.iclr.cc/paper_files/paper/2025/hash/7e3767db483c942b883eb4f8cfb74e31-Abstract-Conference.html) / [官方代码与榜单](https://github.com/openai/mle-bench)

## 4. 与金牌/冠军实际研究的差距：需要可证伪的能力划分

把工作区分成三层：

**L1 已定义问题的求解**：数据、标签、指标和验证条件固定；模型、特征、参数、代码结构优化。现有 Agent 有较强实证基础。

**L2 求解方式的重构**：从数据观察中构造隐藏实体、时序、任务拆解、中间预测目标、样本表示。已有系统可能做到部分，尚不能普遍认定具备冠军级稳健性。

**L3 对问题与评测的审查**：检验标签、采集机制、分布假设、验证方法是否有效；不同解释竞争；决定是否改写整个研究路线。相关公开评测远未充分隔离和测量这类能力。

注意：L3 不一定总比 L1 更“高级”；很多赛题有清晰、可靠的任务定义。真正的目标是**按需要选择层次**，而不是每场比赛都强行寻找新世界观。

### 4.1 五个可能的瓶颈

1. **分数反馈过于稀疏**：AUC 上升不告诉我们是机制发现、噪声还是泄漏。
2. **行动空间被预先限制**：即使 MCTS 很强，如果可执行操作只有“调整参数/代码”，它也未必搜索到“重建隐含实体”。
3. **证据与解释混淆**：一次实验的指标变化不能自动证明提出的机制解释。
4. **共同思维惯性**：多个同质 Agent 可能复述彼此的先验，导致伪多样性。
5. **不可信的评价循环**：研究者如果能随意修改验证集/目标或反复窥探私有测试，搜索系统可能高效地优化错误对象。

### 4.2 需要额外警惕的反例

- 有些冠军本来就主要是优秀的工程实现、速度、规模化搜索或集成，并没有戏剧性的“发现”。
- 一些所谓“隐藏结构”其实是竞赛特定泄漏，不具备现实迁移价值。
- 某些任务分解假设在一场比赛有效，换数据未必成立。
- 人类也会对 Public Leaderboard 过拟合，也会受惯性、幸存者偏差、事后合理化影响。
- 有时一个强单 Agent + 工具，比多 Agent 协作更有效；协作的成本必须计入。

## 5. 提议的研究系统：从 Solution Search 到 Hypothesis-and-Evidence Search

### 5.1 双层结构

**第一层：可执行方案图（Solution/Experiment Graph）**

代码版本 → 执行日志 → 固定评价 → 错误分析 → 下一候选方案。沿用 AIDE/MLEvolve 一类系统已验证有用的基础设施。

**第二层：问题解释图（Hypothesis/Evidence Graph）**

观察 → 多个可竞争解释 → 可鉴别实验 → 证据强度与反证 → 更新解释 → 重构特征/数据/任务 → 回到可执行方案图。

两层交叉连接：同一个假设可以对应多个实验；同一个实验可以支持、削弱或无法区分多个假设。

### 5.2 建议的节点与关系

**节点类型**：
- Observation：原始观察，附产生它的数据、代码、切分和时间；
- Hypothesis：机制/统计假说，标明可预期现象及可推翻条件；
- Rival Hypothesis：替代解释，而不是“反对者为了反对而反对”；
- Discriminating Test：能区分解释的实验设计；
- Experiment：实际代码、数据、配置、预算和运行记录；
- Evidence：量化结果、误差与不确定性；
- Claim：某个阶段可支持的结论，并标明证据等级；
- Reframing：特征图、样本单位、训练目标、验证方式或任务图的变化；
- Open Question：仍未解决的问题与依赖。

**关系类型**：observed-in、motivates、supports、contradicts、not-discriminated-by、implemented-as、depends-on、supersedes、invalidated-by、generalizes-to。

关键不变式：**“观察”“解释”“实验结果”“决定”不能合并成一个自由文本总结**。记录要允许第三方复盘，能看到一条假设到底经历了哪些正反证据。

### 5.3 职责分配（先用逻辑角色，不必上来部署多个 LLM）

- **Problem Framer**：解析任务、数据生成机制、候选样本单位与时间/群组假设。
- **Hypothesis Generator**：提出不同解释，以及模型之外的操作（实体恢复、标签审计、任务拆解）。
- **Skeptic / Falsifier**：提出替代解释和区分性实验，必须具体指出什么观察会改变判断。
- **Experiment Designer**：固定对照、统计检验与资源计划，避免多变量改动无法归因。
- **Coding/Execution Agent**：在隔离环境实现、运行、保存工件。
- **Independent Evaluator**：程序化重算指标、执行泄漏/时间/群组检查、锁定评测定义。
- **Research Director / Portfolio Manager**：根据证据与预算选择探索、复验、组合或终止路线。
- **Memory Curator**：跨轮整理有效事实与未证实解释，同时维护来源和撤销能力。

角色可以合并；是否要拆成多个 Agent 必须通过实验判断。**裁判独立不意味着完全不变更验证设计**：允许提出变更提案，但需要版本化、理由、独立审查与新的比较基线。

### 5.4 反对—支持—第三结论，不以“辩论胜负”代替证据

一个问题可以有 H_A、H_B，甚至 H_C（两者都不正确、二者同时部分成立、遗漏混杂机制）。裁判不应按措辞自信程度投票，而应依据：

1. 与现有数据的符合程度；
2. 能否做出不同于对手的、可被观察验证的预测；
3. 是否在**预先锁定的**新切分/新群体上复现；
4. 解释是否依赖不允许的未来信息；
5. 测试成本是否合理；
6. 证据不足时是否允许“不判定”。

此外必须有**元研究通道**：周期性质疑“为什么我们只搜索这些操作？为什么坚持当前验证方案？研究分支是否同质化？”此类建议也需要受控实验，不可无证据地改掉整个系统。

### 5.5 上下文管理：不要让单一上下文窗口成为研究记忆

应将长期研究信息拆成：

- **不可变原始工件**：数据版本、代码 SHA、配置、日志、预测；
- **结构化发现记录**：假设、证据、反例、已否定路线；
- **短期工作上下文**：当前任务实际所需的有限材料；
- **高层研究总结**：已较可靠的机制、仍未解决的争议；
- **纠错/撤销记录**：某结论依赖的验证一旦失效，相关结论可一起失效。

记忆检索需要分两类：检索有效先例，和检索**最危险的反例**。只检索成功实验会强化既有框架；只压缩分数较好的路线会抹去潜在突破点。所有摘要应能追溯到原始工件，必要时重算而不是让模型自行相信总结。

## 6. 怎样科学验证这一想法？

### 6.1 主要实验：盲法复现关键研究发现

选用已有冠军复盘的历史任务，但**对被测 Agent 隐藏冠军复盘及比赛结束后的资料**。不允许浏览赛后讨论区；模型训练中可能已知解法，所以必须披露并研究污染风险，之后还要用新构造且未公开的任务检验。

建议题型：

| 任务 | 结构性发现 | 想检测的能力 |
| --- | --- | --- |
| IEEE-CIS | 恢复隐含身份/分组 | 从匿名模式提出并检验潜在实体解释 |
| Rohlik | 按预测步长/品类竞争重构 | 能否发现任务与特征表示的替代设计 |
| RSNA 2024 | 关键区域定位再分类 | 能否主动提出有效中间任务 |
| 合成匿名时序表 | 已知隐藏实体、时间漂移或泄漏 | 可客观打分的机制发现与假阳性 |
| 全新任务 | 事先设计未知答案/隐藏机制 | 规避历史解法记忆和事后归因 |

允许不同于冠军实现的有效发现；不能把“是否恰好想到冠军技巧”当成唯一标准。

### 6.2 对照系统（同基础模型、同预算、同工具）

- **B0**：强单 Agent + 固定工具 + 标准实验记录。
- **B1**：B0 + 代码搜索树（AIDE 风格）。
- **B2**：B1 + 长期记忆 / 跨分支融合。
- **B3**：B2 + 显式假设—证据图。
- **B4**：B3 + 反证角色及鉴别实验。
- **B5**：B4 + 元研究通道（允许在审计后修订搜索策略与验证策略）。

这不是简单累加比赛；要有必要的反向消融，例如 B4 去掉独立裁判、B3 去掉解释记忆、B2 去掉跨分支共享，以识别真实收益和交互效应。

### 6.3 指标体系：不能只看最终 Kaggle 分数

**结果指标**：预留测试分数、奖牌门槛、运行有效率、任务完成率、跨切分稳健性、集成收益。

**发现指标**（尽量由盲评和程序检查共同完成）：
- 提出结构性假设的数量/质量；
- 关键隐藏机制发现的 precision 与 recall；
- 能否设计区分竞争假设的实验；
- 假设被反驳后是否确实修改后续路线；
- 从异常首次出现到可信发现的时间/成本；
- 有效问题重构带来的独立增益，而不是归功于参数变化；
- 是否产生不可复现的“解释故事”。

**可靠性指标**：泄漏警报真阳性率、假阳性率，错误验证选择比例，多次运行方差、证据可追溯性、结论撤销成功率。

**效率指标**：token、GPU 小时、墙钟时间、失败试验比例、重跑成本、Agent 间无效重复。

任何关于“更会发现问题”的宣称，都应有预注册标准、多个任务与随机种子、置信区间或等效不确定性分析。避免只展示三场案例中的最好一次。

### 6.4 重要的实验安全与公平性

- 不使用竞赛不允许的外部数据；区分真实可用时间与事后才可见的信息。
- 固定可见的数据版本、公开资料截止日期、推理资源预算。
- 使用嵌套/时间/分组验证等合适切分；独立保留最终评测，限制窥探次数。
- 对同一任务的不同系统采用相同算力、LLM 模型、数据、种子范围与可调用工具。
- 记录模型有可能记住冠军方案的污染，不把复现历史技巧自动视为独立发现。
- 系统或评审都可以判断“信息不足以区分竞争假说”。

## 7. 最小实现路线（强调先证伪）

### M0：建立两个可靠的基础件

1. 一套可复现的训练/评测执行器（固定分折、OOF、工件归档、时间/资源上限）。
2. 一个最小的结构化假设登记器（观察、解释、可反驳预期、实验、证据、状态与引用）。

暂不建设复杂多 Agent 群聊、花哨的仪表盘或庞大的长时记忆。

### M1：验证“额外的解释结构”是否值得

在一个合成可测机制任务和一个历史 Kaggle 任务上比较 B1、B3。若记录假设与证据只增加 token、且没有提高关键发现能力，应考虑将结构简化。

### M2：添加反证与第三解释机制

要求一个实验可以给出“支持 A”“支持 B”“均不支持”“不区分”四类结论。验证反证 Agent 是否确实能减少错误发现，而非制造对话噪声。要求每轮批评都连接到具体可执行检验。

### M3：多研究路线与探索预算

引入竞争研究分支、跨分支证据共享、按信息增益与可能收益混合分配预算，比较单 Agent 和多 Agent 的净效益。针对搜索早收敛设置反事实/反先验任务。

### M4：对框架本身做消融

让系统周期性提出“当前搜索操作空间不适合任务”“验证体系需升级”等元假设，但必须在固定预算、审计和版本化的条件下生效。这一层可能收益巨大，也可能产生不稳定性，不能直接默认为必需。

## 8. 可以并行开展的研究想法

1. **问题发现基准**：对合成和真实数据标注隐藏机制、误导线索及鉴别实验，而不是只标注最高分。
2. **搜索操作生成器**：让系统提出新的“研究操作”（如身份恢复、时间窗口反演、任务分解），并测试操作集合扩展是否真正增加发现率。
3. **观点多样性测量**：不同 Agent 的计划、假设、实验是否实质不同？用操作语义和证据依赖，而非表面文本距离衡量。
4. **反证优先队列**：新证据要优先用于打击最脆弱、风险最大的核心假设，而不是持续强化赢家。
5. **验证机制审计**：建立自动检测时间泄漏、群组泄漏、标签构建缺陷和排行榜过拟合的对照测试。
6. **研究记忆的因果贡献**：删除、扰乱或交换部分历史总结，检查是否真正帮助新任务，还是只让 Agent 复述旧建议。
7. **资源分配与信息价值**：比较按预期分数增益、信息增益、失败风险和实验成本进行调度。
8. **从任务重构到迁移**：在新分布/新比赛中测试原有解释能否转移，避免把一次竞赛技巧误判为普遍规律。
9. **跨研究任务的知识治理**：当旧证据被推翻时，如何自动找出所有依赖它的下游结论并撤销。
10. **人类冠军过程数据**：采集有时间戳的实验日志与采访，防止只根据胜利后的复盘来推断他们当时如何发现问题。

## 9. 尚未解决的问题（研究时应保持开放）

- “发现问题”是否可被客观操作化，而不仅是人为解释一个高分方案？
- 若奖励只有分数，能否自发涌现机制理解；若奖励解释质量，是否反而鼓励虚构故事？
- 在何种类型的 Kaggle 任务上，额外假设结构是收益、在何种任务上是负担？
- 需要多少反证压力才有益？过强的批评会不会压制探索和大胆猜测？
- 长期记忆应储存代码与事实、假设与失败，还是策略性摘要？怎样保留不确定性？
- 多 Agent 的互补究竟来自不同模型/知识、不同工具、不同奖励，还是随机探索？
- 允许 Agent 修改自己的评测框架，应由谁批准，如何防止目标漂移？
- Kaggle 的结构性技巧与可迁移的科学发现，究竟有多大的重合？
- 能否通过被测系统从未见过的全新任务，证明真正的独立发现？

## 10. 结论与下一步

**最值得优先检验的命题**：

> 在一个已经可靠的代码/实验搜索器之外，增加可追溯的“观察—竞争解释—鉴别实验—修正/重构问题”机制，是否能提高机器学习研究 Agent 发现隐藏结构的能力，而非只提高模型分数？

下一步不应先建设一支十几个角色的虚拟研究团队。应当先实现一套**受控可复现的实验执行器 + 显式假设证据记录**，在含已知隐藏机制的任务上与强单 Agent 比较。只有当独立收益得到验证，再决定反证 Agent、跨分支搜索和元研究架构值得投入多少复杂度。
